# Live-site and repository audit — 2026-09-25

## Scope and evidence

Reviewed the actual [production catalogue](https://design-spells.hultsan20.workers.dev/), its generated HTML/CSS/JavaScript, generator, canonical README, Workers configuration, MCP implementation and test harness. Compared the separate [0-js reference](https://github.com/FullThrottle83/0-js).

- design-spells baseline: `56355ed73d4de24ff86b38c48a51376fd343b509`.
- 0-js baseline: `adadf4c43b6ca688f2e1445389b82c779028f11a`.
- Production returned HTTP 200 with `content-type: text/html`, `cf-cache-status: HIT`, and `cache-control: public, max-age=0, must-revalidate`.
- Downloaded production HTML and baseline `public/index.html` have identical SHA-256: `9db478c73c3b8e06377a611d9b5d0d1c5a93d89cc49a9ad174839bb122d31c6b`. Findings apply to the deployed version, not merely a similar checkout. The deployed CSS/JS were observed in the browser but not independently hash-compared.
- Browser inspection covered the actual desktop page, a 390px mobile viewport, opening/closing a spell, initial focus, live DOM, and local verification. Automated Chromium tests additionally cover 320, 390, 768 and 1280px with scripting enabled, disabled and the enhancement file blocked. This is not a screen-reader or cross-engine certification.

## Performance and Workers assessment

| Asset | Baseline bytes | PR bytes |
| --- | ---: | ---: |
| HTML | 4,615,950 | 4,637,456 |
| CSS | 65,539 | 66,372 |
| Enhancement JS | 23,996 | 23,817 |

The baseline live document contained **55,308 light-DOM elements**, excluding elements inside shadow roots and iframe documents. All 150 detail panels and quick previews are emitted up front. This is the principal structural performance concern; the page was also slow enough that browser inspection occasionally timed out. That observation is not a controlled timing benchmark.

Local gzip estimates for HTML are 281,360 bytes before and 283,202 bytes after (Python gzip, mtime 0). These are **not observed wire-transfer sizes**. Accessibility names and help text increase decoded HTML by 21,506 bytes; this PR does not claim a payload reduction. Native iframe deferral is the only loading optimization included.

The assets-only `wrangler.json` is appropriate for this static catalogue. Keep Cloudflare Workers Static Assets and the current revalidation strategy. There is no reason to add a Worker request handler, database or client framework for these fixes. A future performance change should compare a build-generated per-spell document approach or shared preview styles against today's fully embedded page, while preserving no-script navigation and stable URLs. Do not hide the cost by moving all rendering into client JavaScript.

No production deployment was performed. No Lighthouse/DevTools trace, CrUX or RUM data was collected; the DevTools tracing connector was unavailable. Consequently this audit makes no claims about measured LCP, INP, CLS, TBT or a Lighthouse score. A repeatable lab trace and actual field data remain separate follow-up work.

## How to use 0-js

0-js is a single **858,455-byte HTML document**, with zero script elements, 150 native details elements and 134 textareas. It is a reference collection, not an installable runtime library; the checkout contains no package manifest, test harness or explicit license file. It also loads fonts from jsDelivr.

Use it as a **selective pattern reference**, not a dependency or wholesale import:

1. Adopt native disclosure and explicit manual-copy guidance. Its `.kod` pattern uses `user-select: all`; this PR applies that principle to existing source blocks without copying its global stylesheet.
2. Keep the existing design-spells `:has()` category/status filters and native popovers. They already deliver the useful zero-JS behavior demonstrated by 0-js.
3. Consider native fragment links for a later per-spell/static-navigation design. Keep stable design-spells IDs; do not introduce 0-js's unrelated IDs as a second catalogue.
4. Do not import all 133 advertised demos, fonts, themes or dated support claims. Any selected technique should be adapted into README, checked for browser support and keyboard/reduced-motion behavior, then generated and tested normally. Clarify licensing before redistributing substantial portions separately.

This preserves one source of truth and avoids a second stylesheet and support matrix. No changes were made to 0-js.

## Validation and limits

Run `npm ci`, `npm run build`, `npm test`, and `git diff --check`. The new `tests/accessibility.spec.mjs` adds eight cases covering no-script/blocked-script behavior, focus, source disclosures, responsive page overflow, preview names, native toggle delivery and iframe attributes. Existing preview and drawer tests remain in place. The long drawer-description test budget now scales with its 73 spell interactions rather than imposing a fixed 60-second total; assertions were not relaxed.

Final validation: **46 Python tests and 160 Chromium tests passed** in a single `npm test` run (browser suite: 2.1 minutes); `git diff --check` passed. Early runs exposed the real tablet overflow and a test action that incorrectly clicked a clipped input instead of its visible label; both were corrected. A separate concurrent run lost its shared test server; final validation ran as one suite. The first complete suite also exhausted the old drawer timeout; the final 73-description test completed in 1.6 minutes within its proportional budget.

WCAG 2.2 AA remains the target, **not a conformance claim**. Screen-reader output, Firefox/Safari behavior, 200% text resize, full 400% zoom behavior, contrast of every state, sticky-header focus occlusion, pointer target spacing, and all interactive demos still require broader validation.
