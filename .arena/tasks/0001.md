## Browser security and reproducibility

- First inspect whether an existing compatible Chromium/browser is available.
- If using the npm-bundled binary, resolve the actual `executablePath` and set it via **Playwright's supported `launchOptions.executablePath`**. Do not pass `@sparticuz/chromium.args` wholesale.
- Playwright normally adds `--no-sandbox` when `chromiumSandbox` is false (its default). Record the **effective, redacted process command line** and actual sandbox-related outcome. If `chromiumSandbox: true` is supported, test it; if it fails, only use an unsandboxed browser for trusted local fixtures.
- **Hard fail** if the effective browser args include `--disable-web-security` or `--allow-running-insecure-content`. Do not silently accept these flags.
- Permit only localhost/127.0.0.1 test-server navigation **and subresource requests**; block all other destinations and disable service workers for the local browser context. Do not pass GH_TOKEN or other credentials into the spawned Chromium process. Never visit arbitrary public URLs with an unsandboxed browser.
- Commit the exact bootstrap/launch/test integration scripts and their configuration, not merely reports and screenshots. Keep binaries, node_modules, temporary secrets and runtime caches out of Git.
