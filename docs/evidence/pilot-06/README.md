# Pilot 06 browser evidence

Chromium 153.0.8010.0; viewport 1440×900 and 390×844; client scripts disabled. [Before](before-contact-sheet.png), [after](after-contact-sheet.png), [after dark/mobile](after-dark-contact-sheet.png). Inspect the full-size PNGs for legibility; contact sheets are navigation aids, not pixel-diff assertions. The `*-observations.json` files contain actual element and viewport rectangles, document scroll extents, active element, link values, computed overlay display/position/opacity, native state and Escape result. For iframe shots the script captures the *actual iframe viewport*, not the whole scrolled frame body. For each ID/width the `hosted`, `iframe` and `download` variants have initial and activated screenshots; the dark sheet contains mobile hosted initial/activated captures. Capture run uses reduced motion to obtain stable final states; the automated suite separately exercises ordinary and reduced motion.

## What was reproduced, before editing

- **ds-97:** one uncontextualized Menu button; a 286×868px modal at desktop and 286×812px on phone (iframe 286×356px). Close received autofocus and Escape closed it in Chromium. `/` resolved to the catalogue, but `/services` and `/contact` returned HTTP **404** locally. Native modal support was already present in this Chromium run; the issue was destination integrity and product quality. Other-engine `closedby` behavior was *not* observed locally.
- **ds-117:** a floating 156×103px auto popover at **x=0, y≈5**, detached from its trigger at both sizes and inside the real iframe. Escape closed it. `/quote`, `/quote?plan=pro`, and `/contact` returned **404**; the two menu labels promised different quote/sales actions that could not be completed. This is an observed placement and destination defect, not merely a CSS.supports concern.
- **ds-131:** opening a manual popover showed “Changes saved” despite no save operation. Escape left `:popover-open` true in Chromium at both sizes. A manual popover also remains open after an outside click; the explicit button is necessary. The old close control was present; the copy and miniature product experience were the defects. **Do not interpret opacity as dismissal.**

## After measurements and inspection

- ds-97 drawer is 325×900 at desktop, 325×844 on phone, 325×388 / 318×388 in the short documentation portals (actual inner widths 1022/356). The modal remains horizontally/vertically contained; top Close and four section links are visible in the 388px portal and internal scrolling accommodates shorter screens. Fragment links exist in every surface. The full-size [390px iframe capture](after-ds-97-390-iframe-active.png) shows the open dialog, not a fake overlay.
- ds-117 anchored popover is 247×148 at desktop, at x=440.5 / y=635.1 with right edge aligned to its actual trigger right=687.5; forced bottom-edge placement flips above. Mobile and iframe fallback use fixed corner placement, 13px from the viewport right/bottom. The screenshot inspection shows readable controls without horizontal overflow; a simulated no-anchor override leaves the popover visible and actionable.
- ds-131 manual notice is 299×95 at desktop and 364×73 at phone, 13px from the viewport edges; iframe widths shrink with the actual portal. The light and dark mobile sheets show the notice below the reading-desk button. The 44px Close remains keyboard reachable; Escape/outside click leave the native manual state open; explicit close removes it and reopening works.

## Reproduction

1. From this branch: `npm ci && npm run build`; `python3 -m http.server 8787 --bind 0.0.0.0 --directory public` in a separate terminal. Bootstrap Arena's Chromium with `node scripts/arena-browser/bootstrap.mjs` where required.
2. `node scripts/pilot06_capture.mjs after` and `node scripts/pilot06_capture.mjs after-dark`. To recreate *before*, use a separate checkout at `bed449b` served on port 8787, and run the capture script from this branch with argument `before` against that server; **do not overwrite a working tree to obtain before captures**. The saved before PNGs here came from the pre-edit generated HTML of `bed449b` for all three surfaces.
3. `python3 scripts/pilot06_contact_sheet.py` (optional Pillow dependency). Browser assertions: `npx playwright test tests/showcase-pilot06.spec.mjs --config playwright.arena.config.mjs`. The `download` Playwright variant executes `file://` of the same generated HTML; the evidence capture uses the served download response, whose bytes are checked equal to the hosted demo by Python.
4. Check local 404 reproduction with `curl -w '%{http_code}' http://127.0.0.1:8787/services` (similarly `/contact`, `/quote`) against the old checkout. Current demos use only `#` fragments with targets in the same file.

Local browser evidence is not screen-reader, physical-device, full zoom/text-resize, or historical-browser evidence. Firefox/WebKit need a separately installed engine or CI; their outcomes are not inferred from Chromium or support strings. No client-side JS was added to the spell or demos. The documentation portal remains sandboxed with `allow-same-origin allow-forms` only.
